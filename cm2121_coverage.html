Methodology

How this analysis was built

Data source

The 3,083 contact pairs come from the PB/Wires duplicate workbook (Snowflake query run 2026-08-05). Pairs were generated by blocking on shared CRD, shared email (any publisher), and shared xDM business team, then scored with Jaro-Winkler name similarity and classified into Same CRD / Definite / Likely / Possible / Name Collision buckets.

Rule simulation

Each Semarchy contact match rule was approximated from golden-level data columns in the CSV. Signals used: N_SHARED_PHONES, N_SHARED_EMAILS, N_SHARED_BIZ_TEAMS, ZIP_MATCH, ADDR_EXACT_MATCH, first/last name equality, firm equality, state equality. Rules were evaluated in Python against all 3,083 pairs.

Rule categories

CategoryMeaning
ExistingRule exists in current Semarchy xDM configuration. Score is at or above the auto-merge threshold for the relevant golden type. Would automatically merge matching pairs if the rule fires at staging time.
Below thresholdRule exists but score (85) is below the strict >90 auto-merge threshold for confirmed goldens. Creates a suggestion group that requires steward confirmation. CM-2121 R8 raises ExactFNLNMNSfxPhone to 92, converting these to auto-merges.
CM-2121Rule change or new rule proposed in CM-2121. Does not yet exist in production. Counts represent pairs that would additionally be covered after these changes are deployed.

ExactContactBusinessTeam caveat (important)

ExactContactBusinessTeam (score 100) is the dominant rule, covering 2,724 pairs. In Semarchy, this rule evaluates staging-level business team master data — it compares the business team memberships of individual publisher records before they are merged into goldens. This analysis queries the golden-level table cm_md_business_team_member, which is populated after matching and survivorship. These may not be equivalent.

If business team master records are not present in staging (e.g., they are derived from the golden layer only), ExactContactBusinessTeam would not fire in the matching engine despite showing coverage here. The pairs would then depend on the remaining rules for coverage.

Overlap

Rules overlap significantly. A pair that satisfies ExactContactBusinessTeam usually also satisfies ExactFNLNMNSfxFirmState (same name, firm, state) and R8 (same name, shared phone). Counts in the Rules tab are raw per-rule totals, not unique attribution. Coverage percentages (covered / not covered) use union logic — a pair is covered if any rule fires on it.

CM-2121 incremental attribution

A pair is attributed to CM-2121 (incremental) only if it is NOT covered by any existing above-threshold rule AND NOT covered by the below-threshold ExactFNLNMNSfxPhone rule, but IS covered by at least one of R5, R6, R8, R9, or R18. This means the 434 pairs covered by R8 are counted as "below-threshold existing" in the attribution model, since R8 raises an existing rule rather than creating a new condition — the net effect is the same but the attribution preserves the distinction between "existing condition, wrong threshold" and "genuinely new coverage."
