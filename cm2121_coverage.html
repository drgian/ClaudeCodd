Methodology

How this analysis was built

Data source

The 3,083 pairs come from the PB/Wires duplicate workbook (Snowflake, run 2026-08-05). Pairs were generated by blocking on shared CRD, shared email, shared phone, and shared xDM business team, then scored with Jaro-Winkler and classified:

BucketClassification rule
DefiniteShared email + JW(full name) ≥ 80 — OR — shared email + shared phone — OR — shared phone + JW(full name) ≥ 85 + no CRD conflict
LikelyExactLastName + JW(full name) ≥ 75 (or ≥ 90 for common last names) + at least one of: shared phone / email / ZIP / address / biz team
Email VariantSame first + last name + firm, with emails differing only by a middle initial character — same person, two records with different email formats

How R12–R14 were derived

R12 and R13 translate the workbook's own detection signals directly into Semarchy match rule conditions. R14 formalizes the email-variant pattern into an explicit rule for the cases not already caught by ExactFNLNSfxFirmState or R10:

RuleWorkbook signalSemarchy equivalent
R12 (403 pairs)ExactLN + JW ≥ 0.75 + biz team, no phone/ZIP/addrExactLN + JW(first) ≥ 0.75 + BizTeam · score 80
R13 (98 pairs)JW(full name) ≥ 0.85 + shared phone, last names similar not exactJW(first) ≥ 0.75 + JW(last) ≥ 0.75 + SharedPhone · score 85
R14 (13 pairs)Emails identical except for a middle initial characterExactFN + ExactLN + EmailVariantMiddleInitial · score 95

Recall — pairs we may have missed

The 3,083 pairs represent only duplicates detectable via the blocking strategies used (shared CRD, email, phone, business team, email-variant pattern). Duplicates sharing none of these signals are invisible to this analysis.
